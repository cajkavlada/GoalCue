## What to build

Use Task history, Project and Milestone importance, explicit user instructions, and corrections to suggest priority and improve future scheduling. Keep Priority separate from Urgency, preserve manual overrides until the user re-enables automatic priority, and explain the reasons behind suggestions.

## Acceptance criteria

- [ ] New Tasks default to normal Priority; users can choose low, normal, high, or critical.
- [ ] Suggestions distinguish Task importance from deadline-derived Urgency and show understandable contributing signals.
- [ ] A manual Priority remains authoritative until the user explicitly enables automatic priority again.
- [ ] Skipping or delaying a Task alone does not lower its priority.
- [ ] The user can correct a suggestion, inspect relevant learned preferences, and remove them.
