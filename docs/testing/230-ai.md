# #230 — AI providers and usage controls

[Issue](https://github.com/cajkavlada/GoalCue/issues/230) · [All guides](README.md)

**Benefit:** choose who pays and which model handles chat/background work, with bounded spending and manual planning available if AI fails.

**Current limit:** this is a backend feature. There is **no AI settings or usage screen** in the web app. Chat only shows whether a connection is enabled. Activation below requires a developer using an authenticated application client; an unauthenticated function call will fail.

## Try: activate a personal connection (developer-assisted)

1. Have the deployment administrator configure `AI_KEY_ENCRYPTION_SECRET` (base64-encoded 32-byte secret) and `AI_MODEL_REVIEWS` for the chosen models. Reviews require real checked pricing, retention, account-settings approval and an expiry within 31 days of the check. Do not use invented prices to bypass activation.
2. Query **`ai.catalog({})`** as your signed-in user. Choose a provider and two models marked available for activation. Catalog entries are the code's allowlist, not proof your provider account can use them; activation verifies that too.
3. Review the provider's retention, billing and account settings, then call **`aiActions.activate`** with:

```js
{
  provider: "openai",
  funding: "personal",
  key: "<your key, supplied privately>",
  chatModel: "<reviewed chat model from catalog>",
  backgroundModel: "<reviewed background model from catalog>",
  monthlyLimit: 1000000,
  warningThreshold: 0.8,
  retentionAccepted: true,
  accountSettingsChecked: true
}
```

4. Query **`ai.status({})`**. Expect enabled, selected models, a masked key and a **$1 limit**: money uses microdollars, so 1,000,000 = $1.
5. Open Planning chat and send a simple question. Query status again: chat spending should increase; background usage should remain separate.

These objects are function arguments, not code to paste into the normal planning chat. See [activation](../../packages/convex/convex/aiActions.ts#L23) and [status](../../packages/convex/convex/ai.ts#L118).

## Try each option

- **Provider:** OpenAI, Anthropic or Gemini, restricted to the catalog. Repeat activation explicitly for a provider change. A failed choice should not silently switch provider/model.
- **Personal funding:** your provider key and chosen monthly ceiling. Billing by that provider remains authoritative; GoalCue cannot count usage by other apps.
- **Owner funding:** administrator sets `AI_OWNER_SUBJECT`, optionally `AI_OWNER_FUNDED_SUBJECTS`, plus `AI_OPENAI_KEY`, `AI_ANTHROPIC_KEY` or `AI_GEMINI_KEY`. Activate with `funding: "owner"` and no personal key. Ungranted users must be rejected. Current limits are $10 owner / $1 invitee, plus shared pools.
- **Chat / background models:** set separately. A developer can call `aiActions.generate` with role `background`, a fresh requestId and prompt `Reply with OK`; compare the two role totals. Background has a quarter-limit subcap, and both roles share the overall ceiling. Selecting a background model does not itself start a background job.
- **Warning threshold:** 0.8 means warning when spent + reserved reaches 80%. Inspect `warning` and `roles` in status; there is no web warning dashboard yet.
- **Monthly limit:** use a small test ceiling that cannot cover the request reservation. Expect refusal before a provider call, even if actual output would be cheap.
- **Retention/account confirmation false:** activation must fail. Expired reviews, unsupported models or an unavailable account/model must fail too.
- **Disable:** call `ai.disable({ removeKey: false })`; chat stops but the stored key remains for reactivation. `removeKey: true` clears it; personal activation then needs a key again.

## Look for on failure

In a development deployment, simulate a provider failure or exhausted allowance. Manual Task/Event editing must still work. No automatic chat-action replay or model fallback should occur. Spending is reserved first and reconciled after success; uncertain charges can remain reserved. Check `spent`, `reserved`, `remaining`, per-role totals and shared `pools` through `ai.status`.

**Blocked acceptance surface:** key entry, provider/model selection, role budgets, warnings and usage are not currently reviewable through a normal-user settings flow.
